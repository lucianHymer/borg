# Borg philosophy: compound knowledge into repos, light touch outside

Core design philosophy for Borg collaborative agent infrastructure: As much as possible, knowledge and workflow definitions should live IN the project repo (compounding knowledge into the repo so the repo works better over time). Borg itself should have the lightest possible touch outside of the repo — only providing infrastructure/plumbing (MCP tools for thread management like create_thread, send_message, etc.). Workflow skills (dev-team, writing-team, review workflows) belong in the project's .claude/skills/workflows/ directory, NOT in Borg's global ~/.claude/ directory. This means: (1) repos work better over time as workflows accumulate, (2) any Claude Code session in the repo knows its workflows even without Borg, (3) different repos can have different team patterns, (4) Borg = plumbing (MCP tools), Repo = intelligence (skills). The user explicitly stated: "The philosophy is as much as possible we are compounding knowledge into the repo so that the repo works better. We don't want heavy tools. We need some tools but we're trying to keep as light of a touch outside of the repo as we can."
